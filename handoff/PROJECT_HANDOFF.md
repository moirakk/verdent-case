# Verdent Growth OS 完整项目交接

交接日期：2026-07-27（北京时间）

## 1. 项目定位

Verdent Growth OS 是一个独立、私有、云端保存的社媒增长工作台。它面向当前负责人个人使用，同时为以后交接给新同事保留清晰流程、模板、数据和权限边界。

它不是自动发布机器人。当前核心闭环是：收集资料 → 核实事实 → 生成内容与制作 Brief → 审核 → 人工复制发布 → 记录链接 → 复盘分析。

界面方向采用桌面工作台：

- 左侧：任务、搜索、筛选、账号与备份入口。
- 顶部：六阶段进度。
- 中间：当前阶段的主要工作内容。
- 右侧：阶段门禁、任务健康度和快捷动作。
- 视觉：Verdent 深绿与荧光绿，克制、专业，以信息密度和可操作性为先。

## 2. 已确认的产品决策

- 主要由一人使用，但数据结构和 SOP 必须便于未来交接。
- 所有原始内容都保留：文字、文件、截图、网页链接和飞书链接。
- 新建任务支持直接粘贴或上传，系统自动识别任务类型与 Brief。
- 对外发布文案一律使用英文；内部界面和分析可使用中文。
- 系统同时保留两种生成方式：
  - 直接生成六个平台英文初稿。
  - 生成可见、可复制、可下载的 AI Prompt。
- 平台文案由负责人自己复制发布；系统不自动代发，也不需要复制提醒。
- 进入系统的资料默认已经完成同事确认，不设置额外 PM 审批步骤。
- 设计同事根据 Brief 提供图片，偶尔提供视频；负责人收到后自行上传。
- 图片、视频、设计文件和正文放在同一任务的素材库中，按类型和最终版本管理。
- 素材支持综合预览，并保留按图片、视频、文档切换的能力。
- 默认北京时间；任务可选择时区；导出时支持标注多个时区。
- 排期按模板自动设置，同时允许任务内临时覆盖。
- 删除任务进入回收站并保留 30 天。
- 云端数据是权威数据，本地浏览器只保存临时缓存。
- 管理员身份由当前负责人保留；其他人必须得到授权后才能使用。
- 现阶段不绑定普通社媒账号作为 OS 登录方式。
- 飞书可作为后续组织连接与资料入口，但真实接入尚未完成。
- 自定义域名目标为 `growth.verdent.ai`，尚未配置。
- 功能优先，保留核心流程，暂不增加装饰性或低价值功能。

## 3. 已完成并上线：v0.4.1

### 3.1 任务与工作流

- 六阶段：收集、核实、制作、审核、发布、复盘。
- 七种任务类型：
  - 版本更新
  - 新模型
  - 编辑内容
  - Builder Story
  - 服务通知
  - 合作活动
  - 事件活动
- 标准流程和紧急流程。
- P0、P1、P2 优先级。
- 任务搜索、状态筛选和当前阶段显示。
- 列表、看板、日历三种视图。
- 任务模板的创建、复用、编辑和删除。
- 30 天回收站。

### 3.2 输入与 Brief

- 可直接粘贴原始文字。
- 新建任务时可上传文本、截图、图片、视频和办公文件。
- 自动推断任务类型。
- 自动抽取主题、版本/模型、厂商、发布时间、上线状态、能力、使用场景、依据、素材、合作方和保密边界。
- 已修复的关键识别问题：
  - `ready` 不再误识别为 `EA`。
  - `No partner campaign` 不再反向识别为存在合作。
  - `No confidential information` 不再反向识别为有保密信息。
  - 官方文档依据、目标日期与时间可自动带入。
  - 多模型或多版本混入同一任务时会提示串线风险。

### 3.3 内容制作

- X、Discord、LinkedIn、Reddit、Instagram、TikTok 六个平台。
- 正式发布任务默认启用 X、Discord、LinkedIn、Reddit。
- 编辑内容默认启用 X、LinkedIn、Instagram、TikTok。
- 六个平台共享同一事实底稿，但分别按平台重写，不做机械裁剪。
- 支持直接生成英文初稿。
- 支持生成结构化 AI Prompt，并可复制或下载。
- 已有文案不会被重新生成操作静默覆盖。
- 海报 Brief 和视频剪辑 Brief。
- 文案快照可用于回退。

### 3.4 最近两条 Verdent 内容校准

`v0.4.1` 将各平台最近两条可验证的 Verdent 官方内容作为最高优先级的语气和格式样本。

- X 基线：Claude Opus 5.0（2026-07-25）、Gemini 3.6 / 3.5（2026-07-23）。
- LinkedIn 公开可索引基线：Claude Sonnet 5、Verdent 2.6.0。
- Reddit 基线：Claude Sonnet 5、Gemini 相关帖子。
- Discord、Instagram、TikTok 在无法公开核对两个样本时必须标记 `VOICE SAMPLE MISSING`。
- 历史内容只控制语气与格式，不能作为当前任务事实来源。
- 当前 Brief 和证据始终高于历史帖子。
- 正式发布不强制制造争议或提问；观点、教程和 Builder Story 才根据内容选择更强 Hook。

### 3.5 审核与发布

- 自动检查：
  - 未确认的上线表达
  - 待确认占位符
  - 夸大营销词
  - 用户数据分析暗示
  - 英文长破折号
  - X 字符长度
  - Reddit 标题/正文结构
  - 多模型主体冲突
- 启用平台必须有排期、发布状态和最终 URL 才算发布完成。
- 目标日期和时间可自动带入各平台并临时覆盖。
- 导出任务时可同时显示北京时间、UTC 和任务选择的其他时区。
- 发布动作仍由负责人手动完成。

### 3.6 素材、数据与复盘

- D1 保存任务、账号、文案、发布记录、复盘数据和工作区修订号。
- R2 保存图片、视频、文档和设计文件。
- 大文件使用分片上传：前端 512 KB 分片；服务端单片上限 768 KB；文件上限 100 MB。
- 素材通过应用私有路由读取，不暴露公开 R2 地址。
- 云端保存失败时浏览器保留最近缓存，但缓存不是权威数据。
- 用修订号阻止旧页面覆盖新页面。
- 支持完整 JSON 备份和恢复。
- 复盘记录曝光、互动和备注。
- 自动计算总曝光、总互动、整体互动率和平台对比。
- 数字输入支持 K、M、B、万、亿。

### 3.7 账号与权限

- 全局账号目录支持官网、X、Discord、LinkedIn、Reddit、Instagram、TikTok。
- 每个任务只选择实际发布账号。
- LinkedIn 可在 Verdent AI 和 Verdent For Business 之间切换。
- 当前站点使用私有访问，管理员为项目负责人。
- 飞书组织登录与成员权限尚未配置。

## 7. 外部平台接入前提与费用提示

- X：需要开发者项目、Bearer Token 和用户 ID；官方 API 按使用量计费。
- Discord：需要 Bot Token、频道 ID 和频道读取权限；通常没有单独 API 调用费。
- LinkedIn：需要公司页管理员授权、组织 ID 和 `r_organization_social` 等相关权限；应用权限审核可能是主要门槛。
- Reddit：当前先使用公开 RSS；若以后需要完整指标或更高频率，应改用官方 OAuth API。
- Instagram：需要 Meta 开发者应用、专业账号和对应 Graph API 授权。
- TikTok：需要开发者应用、Access Token 和 `video.list` 权限。
- 飞书：需要自建应用 App ID / App Secret、回调域名和文档/组织权限。自建应用接入本身通常不等于额外购买飞书套餐，但具体能力、配额和组织策略需要以 Verdent 当前飞书版本为准。

## 9. 安全红线

- 绝不提交、复制或展示真实 Token、Cookie、密码、飞书 App Secret。
- 所有外部平台凭证只保存在托管环境的服务端 Secret。
- 不把未公开 Changelog、Embargo、用户数据、内部截图或原始录屏提交到 Git。
- 不在前端构建产物中注入服务端密钥。
- 外部 API 错误信息对用户显示时必须清洗，避免回显请求头。
- 原始发布数据、链接和快照默认私有。
- 未经管理员授权不自动读取团队或组织数据。
- 不自动发布社媒内容。
- 数据库迁移、云端部署和自定义域名修改前必须先做本地检查和备份确认。

## 10. 验收标准

现有核心工作流的验收：

- 能从原始 Brief 新建任务并自动识别。
- 能经过六阶段到复盘。
- 六平台英文内容可直接生成，也可输出 AI Prompt。
- 图片/视频/文档可上传、读取和归档。
- 启用平台有排期、账号、发布状态和最终 URL。
- 云端数据在刷新后仍存在。
- 复盘数字和平台对比计算正确。
- JSON 备份可导出并恢复。
- `npm run check` 通过。

外部连接完成的验收：

- 每个平台在无凭证、凭证错误、限流、权限不足和成功时都有清晰状态。
- Token 不出现在页面、API 响应、日志、D1 和 Git 中。
- 最近两条样本可以手动刷新并显示来源、链接和同步时间。
- AI Prompt 明确把样本用于 voice/format，而不是 facts。
- API 失败时使用上次成功快照并显示陈旧状态。
- 链接分析标注采集数据和系统推断的边界。
- 完整检查、关键 API 测试和一次本地全流程测试通过后才允许部署。
