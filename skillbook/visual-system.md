# Verdent Skillbook Visual System

## Direction

Verdent Skillbook should feel like a restrained system transmission, not a generic neon cyberpunk clip.

Use Verdent's app-icon green: a cool mint / aqua leaf glow on a black-green base. Keep it controlled. The series should read as:

- case file
- mission control
- terminal archive
- workflow proof
- product-grade short video

It should not read as:

- bright gamer HUD
- glowing hacker wallpaper
- generic Matrix green
- static presentation slide
- normal landing page

## Palette

Core background:

- `#020403` black
- `#06120f` near-black green
- `#071512` Verdent deep green

Primary signal text:

- `#49dca4`

Strong signal text:

- `#7dffe0`

Muted signal:

- `#1f7c68`

Brand accent:

- `#39f6ad`

Cyan highlight:

- `#1fd6ff`

Rule:

Use the bright mint and cyan sparingly for active states, reveal moments, progress, and final lines. Do not use the brightest colors as the default for every line of text.

## Typography

Use terminal-style monospace:

- `"IBM Plex Mono"`
- `"SFMono-Regular"`
- `Consolas`
- `Menlo`
- `monospace`

Text should feel sharp and operational. Avoid oversized glowing text except for the first hook and final payoff.

## Glow

Glow should be low and controlled:

- normal text: 0-5px shadow
- major reveal: 6-14px shadow
- avoid large 30-50px text glows
- use panel borders and contrast instead of heavy neon

## Motion

The rhythm should feel like short-form video editing:

- hook in first 2-3 seconds
- boot sequence should be fast
- no scene should feel like it is waiting
- nodes should snap on quickly
- final before/after should be readable but not slow

Preferred motion:

- quick vertical cuts
- short glitch bursts
- fast type-in
- sequential node activation
- restrained CRT flicker

Avoid:

- slow fades
- long static cards
- floating decorative animation with no information
- constant glow pulsing

## Layout

Format:

- 9:16 portrait
- 1080x1920 safe-area mindset
- important text inside 8-10% margins
- one main idea per scene
- short phrases only

Use:

- thin frames
- diagnostic cards
- case labels
- workflow nodes
- artifact chips
- progress line

Avoid:

- dense paragraphs
- centered slide-like blocks for every scene
- too many simultaneous labels

## Lines And Text

Lines are structural background, not primary content.

Rules:

- lines should sit behind cards, nodes, and text
- lines should be thinner and dimmer than text
- lines should connect to the edge or orbit of an object, not cut through the label
- text containers need enough opaque background to separate from the line layer
- never let a connector, frame, or grid line cross a readable word

If a scene feels busy, reduce line opacity before reducing text size.

## Episode Structure

Every episode should answer:

1. What is the case?
2. What skill is being used?
3. What messy input came in?
4. What transformation happened?
5. What artifact came out?
6. What is the next case?

End line pattern:

`ONE SKILL. ONE WORKFLOW. ONE ARTIFACT.`
